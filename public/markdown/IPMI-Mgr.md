> 서버 관리 주소·자산 정보·IP 할당과 구형 원격 콘솔을 한 화면에서 관리하는 데이터센터 운영 도구

> **읽는 기준:** 구현 내용과 보관된 검증 결과를 기준으로 정리했습니다. KPI의 제안값과 주차별 일정은 후속 검증·개선 계획이며, 달성한 성과나 실제 개발 기간을 의미하지 않습니다.

**대상 사용자:** 데이터센터 운영자, 장비·자산 관리자, 서버 관리자.
**기술 구성:** Python/FastAPI, Pandas, CSV, Handsontable, WebSocket, dnsmasq, Docker, Caddy.
BMC는 서버 전원이 꺼져 있어도 상태 조회나 원격 제어를 수행하는 관리 칩이고, IPMI는 이런 관리를 위한 통신 규격입니다.

## 1. 문제 정의 (Why)

서버의 관리 IP·MAC 주소·자산번호·제조사 정보와 DHCP 할당 상태를 별도 파일에서 관리하면, 주소 변경이나 장비 교체 때 정보가 어긋날 수 있습니다. 자산번호가 중복되면 수정 대상이 모호해지고, 구형 원격 콘솔은 장비 세대마다 준비가 필요합니다.

- **확인 가능한 관리 범위:** 자산 인벤토리, DHCP 리스, 고정 할당 설정, 원격 KVM 세션을 연결하는 코드가 있습니다.
- **확인 가능한 콘솔 범위:** 현재 KVM 유형은 iDRAC6·iDRAC7·iDRAC8·Cisco UCS의 **4개**입니다. 앞의 3개는 같은 Dell Java KVM 이미지를 공유합니다.
- **확인 가능한 운영 제한:** 기본값은 동시 세션 **4개**, 생성 후 **30분**을 넘긴 세션 자동 정리입니다. 실제 설정으로 변경할 수 있습니다.
- **미확보 손실 수치:** 주소 불일치 건수, 잘못된 장비 수정 횟수, 장비 1대당 접속 준비 시간은 미측정입니다.

## 2. 해결책과 목표 (What)

엑셀처럼 편집하는 웹 인벤토리를 중심으로 주소 할당·장비 감지·원격 콘솔을 연결합니다. 기존 CSV·Excel 파일을 가져오고 내보내는 기능도 제공합니다.

**현재 확인한 해결책**

- 서버 정보 CRUD, 그룹·검색·필터, CSV/Excel 가져오기·내보내기.
- 파일 락과 임시 파일 교체를 사용한 CSV 저장, 중복 자산번호에서 MAC 주소를 함께 사용한 대상 식별.
- dnsmasq 설정 생성·검증·적용, DHCP 리스 조회.
- 선택적 방화벽 API 조회와 인벤토리 대조·반영. 방화벽으로 설정을 쓰는 기능은 없습니다.
- BMC 제조사 감지, Dell·Cisco KVM 컨테이너 관리와 ISO 디렉터리 연결.
- 선택적 API 키·Basic 인증, API·내보내기에서 BMC 비밀번호 제외.

| KPI | 현재 확인 상태 | 제안 목표 | 측정 방법 |
|---|---|---|---|
| 인벤토리와 고정 할당 일치 | 대조·설정 생성 기능 존재, 현장 불일치율 미측정 | 시범 장비 30대의 승인된 MAC/IP 매핑 100% 일치 | 인벤토리·생성 설정·실제 할당 대조 |
| 잘못된 대상 수정 | MAC 기반 식별·중복 처리 구현 | 정의한 중복·정렬 시험에서 오수정 0건 | 같은 자산번호와 다른 MAC을 가진 자료로 검사 |
| 관리 화면의 접속 준비 시간 | 기존 기준값 미측정 | 장비 탐색~KVM 준비 시간 중앙값 50% 단축 | 동일한 지원 장비 10대로 수동 방식과 비교 |
| 내보내기 비밀번호 노출 | 비밀번호 제외 로직 존재 | API·CSV·Excel 시험의 비밀번호 노출 0건 | 가짜 비밀번호를 넣은 시험 데이터 확인 |

## 3. 범위 및 실행 계획 (How)

### 포함 범위

단일 운영 호스트의 CSV 기반 인벤토리, 그룹 편집, DHCP 조회·설정 생성, 방화벽 읽기 연동, 제조사 감지, 지원 KVM 실행·종료와 설치 구성을 대상으로 합니다.

### 제외 범위

- 모든 장비에 대한 범용 IPMI 명령·전원·펌웨어 관리 플랫폼 구현.
- 모든 제조사의 KVM 지원. 제조사 감지와 콘솔 호환성은 별개입니다.
- 방화벽 고정 매핑으로의 자동 쓰기.
- 대규모 다중 호스트 DB와 사용자별 세밀한 권한·완전한 감사 추적.
- 설정 적용의 무중단 보증. 현재 settings.yaml은 dnsmasq 재시작 명령을 사용합니다.

### 마일스톤 — 후속 계획안

| 기간 | 실행 내용 | 완료 기준 |
|---|---|---|
| 1~2주차 | 시범 장비 30대의 주소·자산 정보 정리, 기준 시간 측정 | 중복·누락 항목 및 기준표 확정 |
| 3~4주차 | 인벤토리·가져오기·그룹·제조사 감지 검증 | 중복 식별과 비밀번호 제외 시험 통과 |
| 5~6주차 | DHCP 설정과 방화벽 조회·KVM 연동 시험 | 장비별 실제 접속 결과와 적용 영향 기록 |
| 7~8주차 | 인증·HTTPS·동시 저장·백업 복구 시험 | 일치율·준비 시간·운영 제한 보고서 |

## 4. 작동 방식 (Work)

**자산 정보·주소 입력 → CSV 저장·외부 상태 대조 → 주소 설정 또는 KVM 연결 → 관리 화면 갱신**

1. **데이터 유입:** 운영자가 그리드에서 서버 정보를 편집하거나 CSV·Excel을 업로드합니다. 시스템은 DHCP 리스와 선택적 방화벽 정보를 읽습니다.
2. **시스템 처리:** 서버가 MAC/IP 등을 검증하고 파일 락 아래 CSV를 저장합니다. 설정 생성 요청에서는 인벤토리로 dnsmasq 파일을 만들고 검증·적용합니다. KVM 요청에서는 장비 유형에 맞는 컨테이너를 준비합니다.
3. **결과 제공:** 웹 화면에서 자산·주소·리스 상태·감지 결과를 확인하고 KVM 화면으로 이동합니다. Cisco 유형은 새 JNLP 업로드가 추가로 필요합니다.

WebSocket은 변경 사항과 리스 상태를 화면에 전달합니다. 인벤토리의 기준 저장소는 데이터베이스가 아닌 CSV 파일입니다.

## 5. 리스크 및 기대 효과 (Result)

| 리스크 | 대응 계획 |
|---|---|
| 큰 CSV를 매번 다시 써 저장이 느려짐 | 레코드 수·동시 편집 수에 따른 지연 측정, 한계 도달 시 SQLite/PostgreSQL 전환 |
| DHCP 설정 오류나 적용 중 서비스 중단 | 적용 전 검증·변경 내역 확인, 기존 설정 백업, 관리망 시험과 복구 절차 준비 |
| 인증 비활성 기본값과 Docker 소켓 권한 | 운영에서 인증·HTTPS를 구성하고, KVM이 불필요하면 Docker 기능과 소켓 연결 비활성화 |
| KVM 펌웨어·라이브러리 차이 | 장비·펌웨어별 호환 표 관리, 실패 시 장비 기본 관리 화면 또는 별도 콘솔 사용 |
| 여러 작업자가 변경 이력을 추적하기 어려움 | 변경 승인·백업 절차를 우선 적용하고 감사 로그·역할별 권한은 후속 과제로 명시 |

**기대 효과**

- **정량 목표:** 시범 30대 매핑 100% 일치, 정의한 오수정·비밀번호 노출 0건, KVM 준비 시간 50% 단축.
- **정성 효과:** 장비 정보·관리 주소·실제 할당 상태를 한곳에서 확인하고 구형 콘솔 준비 절차를 줄일 수 있습니다.
- **현재 성과의 경계:** 인벤토리와 네트워크·콘솔 연동을 확인했습니다. DHCP 무중단 적용, 모든 제조사 지원, 운영 사고 감소를 보증하지 않습니다.
